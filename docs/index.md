# 单页技术洞察汇报

`create-single-page-tech-report` 将技术论文、近期技术进展、技术结果或事件材料压缩成一页可编辑中文 PowerPoint。核心目标是用一句话标题、证据主导的正文和面向研究或技术路径决策者的底部洞察，在一页内讲清楚发生了什么、为什么重要以及下一步应关注什么。

## 逻辑视图

| 层次 | 职责与边界 |
| --- | --- |
| 来源理解 | 读取用户提供的材料与附带图表，区分明确事实、证据边界和必要推断；不补造数据。 |
| 故事组织 | 技术论文采用“问题 → 方法 → 效果”；事件快报按材料事实组织，不套用未经定义的专属模板。 |
| 页面设计 | 选择两栏、三栏、四栏或纵向卡片，使用红灰主色、微软雅黑与 Arial，多行文本使用 `150%` 行距，并保留可编辑性。 |
| 兼容性规范化 | 导出后清除阻碍选择、移动、缩放、组合和文本编辑的锁，并移除会覆盖整框改色的冗余 run 级颜色。 |
| 交付校验 | 自动检查 PPTX、单页、无动画时序、无常规编辑锁、无冗余 run 级颜色和可检测多行文本的 `150%` 行距；人工检查语义、证据、字体、自动换行、溢出、遮挡和图表清晰度。 |

主要输入是来源材料、原始图片或表格以及目标读者；主要输出是 `.pptx`、渲染预览和校验摘要。临时产物统一写入 workspace 的 `.tmp/create-single-page-tech-report/<task-name>/`。

## 运行视图

```text
用户 prompt 与来源材料
  -> 主 Agent 盘点事实、图表和证据边界
  -> 选择论文或事件组织方式
  -> 设计一页信息结构
  -> 创建可编辑 PPTX
  -> 规范化对象锁与文本颜色继承
  -> 渲染预览并检查视觉问题
  -> 运行单页/动画/可编辑性结构校验
  -> 人工复核内容与视觉规则
  -> 交付 PPTX、预览和校验摘要
```

## 开发视图

| 文件或目录 | 职责 |
| --- | --- |
| `SKILL.md` | Agent 的完整制作规则、版式、字体、颜色和验收清单。 |
| `agents/openai.yaml` | Codex skill 列表中的展示名称、简介和默认 prompt。 |
| `verify_dependencies.py` | 检查命令行依赖并说明无法脚本化探测的 Agent 能力。 |
| `scripts/normalize_groupability.py` | 清除常规编辑锁和与段落默认色重复的 run 级颜色，并原子写回 PPTX。 |
| `scripts/validate_single_page_report.py` | 校验 PPTX 包结构、单页约束、动画时序节点、常规编辑锁、冗余 run 级颜色和可检测多行文本的 `150%` 行距。 |
| `docs/` | 面向文档站的能力、用法、依赖和架构说明。 |

## 多 Agent 职责边界

本 skill 默认由一个主 Agent 完成，不强制启动子 Agent 或 checker。

| 角色 | 职责 | 禁止事项与交接边界 |
| --- | --- | --- |
| 主 Agent | 理解来源、组织故事、制作 PPTX、渲染预览并完成校验。 | 不猜测事实，不用装饰替代技术解释，不把中间产物写进 skill 目录。 |
| 可选来源分析 Agent | 在材料复杂时整理事实、证据边界和图表对应关系。 | 不决定页面视觉，不修改最终 PPTX；交接结构化事实与来源定位。 |
| 可选视觉 checker | 只根据渲染图检查溢出、遮挡、对齐、层级和可读性。 | 不重写技术结论；把逐项问题交回主 Agent 修订。 |
| 用户 | 提供来源材料、目标读者和正式输出路径。 | 未提供的信息不应被 Agent 当作事实补全。 |

## 边界

- 严格生成 1 页，不支持多页 deck。
- 不使用动画。
- 机器校验不能替代内容真实性和视觉质量复核。
- 没有相关原图且 ImageGen 不可用时，使用可编辑基础图形降级，并明确说明。
